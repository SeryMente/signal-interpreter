# Signal Interpreter 0.10.26 — Atribución de hablantes por fuente de audio

## Antes

La versión 0.10.25 incorporó un preview bilingüe para el audio de pestaña y el micrófono, pero dos etapas de la presentación podían contradecir la fuente capturada:

- El service worker podía reclasificar audio de pestaña como LEP cuando el reconocedor detectaba español.
- El overlay volvía a convertir cualquier fila en español en LEP y pintaba el rol a partir del idioma, ignorando la fuente de la intervención.

Ese acoplamiento confundía **idioma** con **identidad del hablante**: un cliente que hablara español podía aparecer como LEP y una intervención del LEP en inglés podía presentarse como cliente. También debilitaba la deduplicación porque ambas intervenciones podían mezclarse en el mismo carril.

## Cambio

- En Cloud Interpreter, la salida del preview conserva el origen: el audio de pestaña se atribuye a `cliente` y el preview del micrófono a `yo` (LEP). La clasificación inglés/español se conserva como metadato lingüístico, no como sustituto del origen.
- `addRow` normaliza la fuente sin reasignarla automáticamente por idioma.
- El render calcula el rol mediante `roleForSource(item.source, language)`, respetando la procedencia de la fila.
- YouTube conserva su asignación explícita por idioma: su preview de prueba utiliza una única pista de audio de pestaña y no comparte la semántica de fuentes separadas cliente/micrófono de Cloud Interpreter.
- Se añaden regresiones para `cliente + español → CLIENTE`, `LEP + inglés → LEP`, y aserciones de auditoría para que el pipeline conserve la fuente hasta el render.
- La extensión y las pruebas que validan la versión se incrementan a 0.10.26.

## Motivo

La etiqueta de hablante debe proceder del canal de captura que originó la intervención cuando esa fuente es conocida. El idioma ayuda a interpretar el contenido, pero no demuestra quién habló. Separar ambas dimensiones mantiene correctos el carril visual, la deduplicación y la revisión posterior.

## Validación

Los workflows de GitHub Actions deben validar el SHA de esta versión antes de integrar los cambios. La evidencia automatizada cubre la lógica y las aserciones de regresión. No equivale a una llamada bilingüe real.

## Resultado esperado

- El audio de pestaña en Cloud Interpreter permanece en el carril CLIENTE, aunque se reconozca español.
- El audio del micrófono del intérprete permanece en el carril LEP, aunque se reconozca inglés.
- La etiqueta de idioma sigue mostrando ENGLISH / ESPAÑOL de acuerdo con el resultado del reconocedor.
- Las intervenciones de fuentes distintas no se fusionan debido únicamente a compartir el idioma.

## Límites

La asignación supone que el audio de pestaña corresponde al interlocutor remoto y que el micrófono corresponde al intérprete local. Las pruebas automatizadas no pueden certificar una llamada acústica real, la calidad del micrófono, el comportamiento de Chrome Live Caption ni la latencia percibida. Esas condiciones requieren una comprobación funcional en Chrome durante una llamada autorizada.
