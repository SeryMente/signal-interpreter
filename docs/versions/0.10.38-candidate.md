# Candidata Signal Interpreter 0.10.38 — puente estable y control de overlays

**Estado: candidata no liberada; no aceptada en Windows.**

## Motivo

La ejecución de \`INSTALAR.ps1\` en Windows PowerShell 5.1 interpretó el array JSON completo de huellas como una sola entrada y generó \`Missing payload file\` con todos los nombres concatenados. La versión candidata normaliza el inventario de forma recursiva y valida que cada elemento sea un objeto independiente con \`path\` y \`sha256\`.

## Cambios propuestos

- Instalar el host nativo en \`%LOCALAPPDATA%\\SignalInterpreter\\NativeMessagingHost\` y registrar en HKCU un manifiesto que apunte a esa ruta estable.
- Verificar las huellas del paquete y el protocolo Native Messaging tanto sobre el ejecutable incluido como sobre la ruta instalada.
- Al recargar, remover hosts residuales de los dos overlays antes de montar los nuevos, para evitar duplicados que tapen el dialpad.
- Agregar switch global **Mostrar overlays** y atajo \`Ctrl+Shift+Y\` para ocultar/restaurar ambos overlays sin cambiar las preferencias particulares ni alterar Auto-Answer.

## Criterios de aceptación pendientes

1. Las pruebas CI de la revisión exacta concluyen satisfactoriamente.
2. En Windows PowerShell 5.1, el instalador concluye con todas las huellas en PASS, \`NATIVE_MESSAGING_PROTOCOL=PASS\` y registro verificado.
3. Chrome, en una prueba segura en PC-8, conserva un único overlay de subtítulos y un único overlay de ingresos después de recargar la extensión.
4. En llamada de prueba autorizada, el switch y \`Ctrl+Shift+Y\` ocultan/restauran ambos overlays sin alterar audio, dialpad ni Auto-Answer.
5. Deep Freeze no revierte el ejecutable en \`%LOCALAPPDATA%\` ni la clave HKCU tras reiniciar en modo protegido.

No se modifica el lector C#, no se añade captura de micrófono ni de audio y no se fusiona la candidata a \`main\`. Pasar pruebas estáticas o el probe nativo no demuestra transcripción real en una llamada.
