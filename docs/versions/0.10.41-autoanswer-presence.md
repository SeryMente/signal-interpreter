# Signal Interpreter 0.10.41 — corrección de presencia para Auto-Answer

## Corrección
- La autorización explícita de Auto-Answer se conserva en `chrome.storage.session`, permitiendo recuperar el estado tras la suspensión/reinicio normal del service worker Manifest V3.
- Al restaurar, se comprueban de nuevo la identidad de la extensión, el intervalo de inactividad, el estado real del sistema mediante `chrome.idle.queryState`, la configuración Auto-Answer y el bloqueo de laboratorio.
- Inactividad/bloqueo, pausa manual, fin de sesión, desactivación de Auto-Answer o bloqueo de laboratorio eliminan la autorización de sesión.
- El almacenamiento de sesión se elimina al recargar/actualizar/deshabilitar la extensión o reiniciar Chrome; se exige nueva confirmación explícita después de esos eventos.
- La identificación de la ruta de perfil acepta la barra final, query y fragmento sin abrir rutas secundarias, otros orígenes ni subframes.

## Pruebas sintéticas
- Presencia: 60/60 PASS.
- Flujo de conexión/Connect: 33/33 PASS.
- Sustitución/duplicación del runtime: 15/15 PASS.
- `node --check` de los archivos JS y pruebas afectados: PASS.
- `git diff --check`: PASS.

Estas pruebas usan APIs Chrome y DOM sintéticos. No equivalen a aceptación de una llamada real en Windows.

## Límites de operación
- OPI verificada sigue siendo el único caso elegible.
- VRI, modalidad desconocida, subframes, perfil no autorizado, estado de inactividad, bloqueo y laboratorio siguen bloqueados.
- No se ha recargado Chrome, no se ha contestado/manipulado una llamada real y no se declara aceptación funcional.
- La siguiente compuerta es la recarga manual del operador y una observación controlada de llamadas entrantes elegibles/no elegibles.
