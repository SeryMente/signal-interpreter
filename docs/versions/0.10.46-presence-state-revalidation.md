# Signal Interpreter 0.10.46 — revalidación robusta de presencia

## Antes

En G12, la extensión detectaba correctamente una llamada OPI entrante, encontraba Connect habilitado y registraba timbrado, pero no pulsaba Connect porque el guard había sido desarmado con `IDLE_OR_LOCKED_CONFIRM_AGAIN`. El código agrupaba bajo la misma razón los estados Chrome Idle `idle`, `locked` y `unavailable`, y también revocaba ante excepciones transitorias de APIs del navegador.

## Cambio

La versión 0.10.46 separa la señal de inactividad confirmada, el bloqueo de Windows y la indisponibilidad de la consulta. Los estados idle/locked confirmados siguen revocando la autorización. Una consulta unavailable bloquea la llamada actual, conserva el consentimiento de disponibilidad de la sesión y programa una nueva verificación; nunca concede autorización por sí sola. Las excepciones temporales de APIs de storage/tabs bloquean el intento, pero no destruyen por sí solas la autorización explícita.

Se añade diagnóstico mínimo de presencia (estado, disparador, marca temporal y código de error saneado) sin audio ni contenido de llamadas. El popup explica que el umbral mide ausencia de entrada de teclado/ratón, no presencia física. Los valores 1, 3, 5 y 10 minutos siguen siendo opciones de selección explícita; no se impone un nuevo predeterminado.

El paquete conserva la corrección previa del indicador global de pestañas: el azul fuera de Cloud Interpreter solo se muestra cuando Cloud Interpreter está verde; si el estado global está rojo, gris o ámbar, el resto refleja ese estado.

## Motivo

Evitar que un timeout/error temporal de Chrome sea tratado como si Windows hubiera confirmado una ausencia o bloqueo, sin relajar el principio fail-closed ni eliminar una revocación real de presencia.

## Resultado y límites

Las pruebas sintéticas y la integridad de los 59 archivos se ejecutaron localmente; resultados detallados en [la crónica G12 de 0.10.46](../frentes/signal-interpreter/cronica/C-SIGNAL-PRESENCE-01046-G12-20261108.md). La candidata está en PR #73, rama `work/g12-autoanswer-revalidation`, todavía no fusionada. No hubo recarga de Chrome, prueba de llamada real ni aceptación Windows. El cambio no garantiza que todas las llamadas se contesten: una llamada recibida cuando el operador esté realmente inactivo/bloqueado, la modalidad sea VRI/desconocida o el perfil no esté autorizado continúa sin contestación automática.
