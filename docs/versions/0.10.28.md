# Signal Interpreter 0.10.28 — Informe persistente de observabilidad al cierre de llamada

## Objetivo

Cerrar la brecha entre observar que Cloud Interpreter llegó a la pantalla de estrellas y entregar a la siguiente sesión de desarrollo un informe de diagnóstico suficientemente rico para continuar la investigación sin reconstruir manualmente el estado de la llamada.

## Cambios

- El content script emite `CALL_RATING_STARS_CONFIRMED` solo cuando la ruta de calificación y evidencia estructural limitada confirman que las estrellas están visibles.
- La confirmación incorpora contadores y método de detección, pero no el valor elegido ni una afirmación de que el rating se envió.
- Los eventos del content script quedan correlacionados con `callId` en payload, sesión y contexto. Se emite una captura final de rendimiento con vínculo explícito a la llamada.
- El checkpoint `call-ended` incluye campos finales permitidos de la llamada, duración, modalidad, estado, fuente de cierre, facturación estimada e ingresos.
- La llamada espera a la conciliación de ingresos y después añade el checkpoint final.
- La sincronización implementa `flushThrough(sequence, checkpoint)`: drena varios batches hasta que GitHub Relay acepta la secuencia final. Persiste el objetivo y reintenta si hay red, cuota o backlog; no confunde un intento con entrega confirmada.
- GitHub Actions transforma los eventos saneados en informes individuales JSON y Markdown, índice histórico y puntero al último informe.
- El informe agrega eventos por acción/categoría/componente/severidad, fallos y warnings con reason codes, señales de micrófono/audio/transcripción, rendimiento/red, media, plataforma, facturación y recuperación. También enumera las señales que faltan.
- Auditoría de paquete e integración continua comprueban la estructura, los punteros, privacidad y casos de regresión.

## Artefactos que consultará la siguiente sesión

- `observations/latest/latest-call-report.md`: punto de entrada de lectura rápida.
- `observations/latest/latest-call-report.json`: informe estructurado más reciente.
- `observations/call-reports/index.json`: índice con referencias opacas y estado.
- `observations/call-reports/YYYY-MM-DD/call-<opaque-ref>.json`: informe por llamada.
- `observations/latest/latest.json` y `observations/batches/`: evidencia original saneada para reconstruir el informe.

## Definición de completitud

Un informe queda `complete` solo cuando se recibió el checkpoint final, existe el registro final de llamada y se observó un timestamp de fin. En otro caso permanece `partial` y enumera las señales que faltan. El reporte distingue estrellas visibles, puntuación seleccionada y envío de valoración; las dos últimas no se infieren a partir de la ruta.

## Contrato de privacidad

Los informes no incluyen audio, transcripciones crudas, contenido de la conversación, HTML/CSS/JavaScript completos, credenciales o valores de calificación. La llamada se representa mediante un hash opaco, los nombres de recursos se normalizan y los errores se expresan con motivo/tipo saneado, no con sus mensajes brutos.

## Arquitectura y validación

La ruta permanece `Chrome MV3 → IndexedDB → Vercel Relay existente → observations/inbox → GitHub Actions → call-reports/latest`. No se añade endpoint Relay ni servicio local de Windows, por lo que no se solicita un deployment Vercel nuevo.

La suite de GitHub Actions valida sintaxis, regresiones del núcleo, construcción del paquete y el nuevo fixture del informe. Esto demuestra el contrato de código y el procesamiento de batches sintéticos; no prueba todavía una llamada real en Cloud Interpreter. Tras instalar 0.10.28, la primera llamada que termine con la pantalla de calificación generará evidencia real para verificar la heurística de estrellas y el drenaje extremo a extremo.
