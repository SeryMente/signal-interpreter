# Signal Interpreter 0.10.21 — Baseline seguro de ingresos al iniciar llamada

## Antes
El arranque de llamada iniciaba la sincronización oficial mientras el overlay calculaba el ingreso activo. Si el espejo oficial se capturaba después del inicio real, podía utilizarse como punto de partida y volver a sumar el ingreso de la llamada en curso. El conteo diario también utilizaba una fecha distinta de la fecha medida de inicio.

## Cambio
El estado de ingresos por llamada se captura antes de solicitar la sincronización oficial. Solo se acepta un espejo oficial si su marca temporal no es posterior al inicio medido. Si no hay evidencia temporal válida, se utiliza un baseline local explícito a partir de llamadas registradas; una captura posterior no puede reemplazar ese baseline durante la llamada. Se rechazan además los importes oficiales incompletos (earnedUsd nulo o vacío). El bucket de dailyCalls utiliza measuredStartAt.

## Motivo
Impedir el doble conteo de ingresos y evitar que una sincronización iniciada después de contestar se trate como si fuera una lectura anterior a la llamada.

## Resultado
El overlay distingue un baseline oficial temporalmente seguro de un respaldo local, y acumula el ingreso activo una sola vez sobre el baseline guardado. Se agregaron pruebas para espejos anteriores y posteriores al inicio, baseline local persistente, importes oficiales incompletos y baseline almacenado inseguro. La liberación queda condicionada a CI y comprobación operativa; las pruebas automatizadas no sustituyen una llamada real.

## Validación
Estado de validación al crear esta narrativa: pendiente de CI hospedado y de prueba de una llamada real. No se declara completa la liberación hasta obtener ambas evidencias.
